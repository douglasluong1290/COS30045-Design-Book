D3 CHART CODING PLAN — COS30045 Data Storytelling Page
========================================================
Branch: claude/data-storytelling-page-IKWiT
Source spec: charts_features.txt
Stack: vanilla JS + Vite, D3 v7, SheetJS (xlsx) for the data loader

----------------------------------------------------------------
0. WHAT WAS BUILT
----------------------------------------------------------------
A single data loader + four D3 chart modules, all orchestrated by
main.js:

    src/data/load-data.js              — opens xlsx, hands each chart its sheet
    src/charts/theme.js                — shared tokens + helpers
    src/charts/ch1-trend.js            — national line, phase-coloured
    src/charts/ch2-states.js           — map + click-drill (line × bar)
    src/charts/ch3-demographics.js     — small-multiples horizontal bars
    src/charts/ch4-roaduser.js         — dumbbell chart

main.js boots scrollytelling, calls the loader once, then passes the
relevant sheets into each chart's init function. Each chart aggregates
its own data from the raw rows.

----------------------------------------------------------------
1. DATA PIPELINE — single JavaScript loader
----------------------------------------------------------------
The workbook is read in the browser at page load. No Python step, no
pre-baked JSON.

Dependencies
    npm install d3 xlsx

Assets that must sit under public/ (Vite serves this directory at
the base URL):
    public/data/transformed_datasets.xlsx   (copied from thanh_analysis/)
    public/data/au-states.geojson           (still required by chart 2)

src/data/load-data.js — the only file that knows about the workbook:

    import * as XLSX from 'xlsx'
    import * as d3 from 'd3'

    /**
     * Open the workbook once, parse every sheet into an array of
     * objects. Each sheet is converted to a CSV string via SheetJS
     * and then handed to d3.csvParse, so D3 owns the row-parsing
     * end of the pipeline and chart modules speak D3-native data.
     *
     * Returns { sheetName: [row, row, ...] }
     */
    export async function loadDatasets(
      path = 'data/transformed_datasets.xlsx'
    ) {
      const buf = await fetch(path).then((r) => r.arrayBuffer())
      const wb = XLSX.read(buf, { type: 'array' })
      const sheets = {}
      for (const name of wb.SheetNames) {
        const csv = XLSX.utils.sheet_to_csv(wb.Sheets[name])
        // d3.autoType coerces numeric columns so chart aggregations can
        // drop the +d['Count of cases'] dance.
        sheets[name] = d3.csvParse(csv, d3.autoType)
      }
      return sheets
    }

Why d3.csvParse and not d3.csv
    d3.csv() fetches a CSV from a URL — fine when CSVs exist as files.
    Here SheetJS hands us CSV strings already in memory, so the
    fetch-the-CSV step is redundant. d3.csvParse() runs the same row
    parser without a network round-trip. Net result: the loader makes
    ONE network request (the xlsx itself) regardless of how many
    sheets the workbook contains.

Why a single loader file
    - The xlsx is fetched once per page load, not 6× (one per chart).
    - Each chart gets a clean, pre-parsed array — no error-handling
      boilerplate is duplicated.
    - Swapping the source workbook is a one-line change.

Per-chart filtering — now lives next to the chart, not at build time.
Each chart receives the raw sheet and filters before aggregating:
    - chart 4 drops rows where road_user === "Not applicable".
    - chart 3 drops rows whose age_band reads
                                "missing" / "not stated" / "unknown".
    - chart 1 computes the admission category inside ch1-trend.js
      using the spec's SWITCH rule on Calendar year.

2. SHARED MODULE — src/charts/theme.js
----------------------------------------------------------------
Exports
    colors          — read from CSS custom properties at runtime, so
                      the charts inherit dark mode automatically.
    phasePalette    — three-tone admission palette keyed by category
                      label; reused by ch1 and the VIC/NSW drill line
                      in ch2.
    fmt             — d3.format wrappers (int with commas, compact
                      1.2M / 250k).
    mountSvg        — empties .placeholder-canvas, mounts a responsive
                      viewBox-based <svg>, returns the d3 selection.
    drawGrid        — dotted-light-gray grid (vertical + horizontal),
                      matches the spec's "dotted light gray grid".
    makeTooltip     — floating div attached to <body>, position: fixed,
                      follows the cursor. .show(html, ev) / .move / .hide.

----------------------------------------------------------------
File:    src/charts/ch1-trend.js
Sheet:   publication
Signature: initCh1(publicationRows)

Aggregation inside the chart
    const byYear = d3.rollup(
      publicationRows,
      (v) => d3.sum(v, (r) => r.Hospitalisations),
      (r) => r['Calendar year']
    )
    // -> Map<year, hospitalisations>
    // then map into [{ year, hospitalisations, admission }] applying
    // the SWITCH (2011, 2012–2016, ≥2017) for the admission column.

    Phase-coloured line segments (3 colours from phasePalette),
    dotted-grey grid, both axes with titles, dot per year.

Interaction
    Invisible vertical hit-rect per year → tooltip with year + cases.
    Hovered point grows r 5 → 8.

Legend
    Drawn in the SVG top-left margin from phasePalette.

4. CHART 2 — Map + click-drill  (#chart-2-states)
----------------------------------------------------------------
File:    src/charts/ch2-states.js
Sheets:  state_summary (totals + trend), population (drill bar)
Geo:     public/data/au-states.geojson (loaded by main.js, injected)
Signature: initCh2(stateSummary, populationRows, geo)

Aggregation inside the chart
    // per-state totals across years (for bubble size)
    const totals = d3.rollups(
      stateSummary,
      (v) => d3.sum(v, (r) => r['count of cases']),
      (r) => r['state or territory']
    )
    // per-state time-series for the drill line
    // population rows are passed through unchanged

Render — MAP layer
    GeoMercator().fitSize() on the 8 features, polygons in accent-bg
    fill + border stroke. State bubble at d3.geoCentroid(feature),
    radius via scaleSqrt, accent fill + state-code label.

Render — DRILL layer
    Triggered by a bubble click — swaps mapLayer.style('display') to
    'none' and shows a back-button + line × bar combo:
        line = cases over years (left Y axis)
        bar  = population over years (right Y axis, behind the line)
    For VIC: line segments are phase-coloured with the 2012 cutover.
    For NSW: phase-coloured with the 2017 cutover.
    Other states: single accent-coloured line.
    A footer legend is added only for VIC/NSW (matches the spec).

Interaction
    Hover bubble → tooltip "total cases · click to see more →".
    In the drill: hover population bar / case dot → year + value.

5. CHART 3 — Small-multiples horizontal bars  (#chart-3-demographics)
----------------------------------------------------------------
File:    src/charts/ch3-demographics.js
Sheet:   publication
Signature: initCh3(publicationRows)

Pre-aggregation inside the chart
    const cleaned = publicationRows.filter(
      (r) => !/missing|not stated|unknown/i.test(r['Age group'] || '')
    )
    // -> d3.rollups grouped by (age band, sex) summing
    //    Count of cases + Bed days.

Render
    One panel per age band, stacked top to bottom. Each panel has
    two side-by-side horizontal bars:
        left  = cases    (accent)
        right = bed days (muted)
    Value label at the right end of each bar (per spec). Vertical
    dotted grid in each panel. Age label anchored to the left.
    AGE_ORDER hardcoded ascending — panels never sort alphabetically.

Slicer (primary interaction)
    In-SVG pill buttons above the panels: [All] [Female] [Male].
    Click → re-aggregate via d3.rollups → d3.transition(450) on bar
    widths + label positions.

6. CHART 4 — Road-user dumbbell  (#chart-4-mechanism)
----------------------------------------------------------------
File:    src/charts/ch4-roaduser.js
Sheet:   publication
Signature: initCh4(publicationRows)

Baked-in filter — first line inside the chart
    const filtered = publicationRows.filter(
      (r) => String(r['Road user']).trim().toLowerCase() !== 'not applicable'
    )
    // Not exposed as a UI toggle. Mirrors the page-level filter
    // in the final pbix.

Aggregation
    d3.rollups(filtered,
      (v) => ({
        cases: d3.sum(v, (r) => r['Count of cases']),
        bed_days: d3.sum(v, (r) => r['Bed days']),
      }),
      (r) => r['Road user']
    )

Render
    Y axis = road user (band scale, ordered by cases descending).
    X axis = shared linear scale spanning max(cases, bed_days).
    Per row: connecting <line>, accent circle at cases, muted circle
    at bed days, value labels next to each dot. Dotted vertical grid.

Legend
    Top-left, two-item: accent dot = cases, muted dot = bed days.

Interaction
    Whole row → both circles r 8 → 11 on hover; tooltip shows road
    user, cases, bed days, and bed-days-per-case ratio.

7. WIRE-UP — src/main.js
----------------------------------------------------------------
    import './style.css'
    import { loadDatasets } from './data/load-data.js'
    import { initCh1 } from './charts/ch1-trend.js'
    import { initCh2 } from './charts/ch2-states.js'
    import { initCh3 } from './charts/ch3-demographics.js'
    import { initCh4 } from './charts/ch4-roaduser.js'

    async function initCharts() {
      try {
        const [sheets, geo] = await Promise.all([
          loadDatasets(),
          fetch('data/au-states.geojson').then((r) => r.json()),
        ])
        initCh1(sheets.publication)
        initCh2(sheets.state_summary, sheets.population, geo)
        initCh3(sheets.publication)
        initCh4(sheets.publication)
      } catch (err) {
        console.error('chart bootstrap failed:', err)
      }
    }

    function boot() {
      initScrollytelling()
      initCharts()
    }

main.js owns the orchestration. Each chart file is purely about
rendering — it receives parsed rows and never touches the network.

The existing scrollytelling glue (IntersectionObserver + stepchange
CustomEvent) is preserved untouched. When step-driven behaviour is
wanted, each module can hook in via:

    const sticky = document.querySelector('#chart-1-trend')
                     .closest('.chart-sticky')
    sticky.addEventListener('stepchange', (e) => onStep(+e.detail.step))

----------------------------------------------------------------
8. STYLING NOTES
----------------------------------------------------------------
- All dimensions read from CSS variables, so dark mode JUST WORKS.
  No JS theming logic needed.
- The .chart-placeholder containers use a hatched canvas in CSS for
  the "no chart yet" state. mountSvg() resets the .placeholder-canvas
  to a plain block so the hatching disappears the moment a chart
  mounts.

----------------------------------------------------------------
9. RUNNING
----------------------------------------------------------------
    npm install
    npm run dev
    npm run build

No Python step. transformed_datasets.xlsx must sit under
public/data/ so Vite serves it; au-states.geojson stays alongside.

If the source workbook changes, just refresh the page — the loader
re-parses on every load. The browser caches the xlsx the same way
it caches any other static asset.

The Vite base path is /cos30045/s104358130/design-book (Swinburne
Mercury deployment). All fetches inside the loader use plain
relative paths (data/foo.xlsx), so the base is applied automatically.
