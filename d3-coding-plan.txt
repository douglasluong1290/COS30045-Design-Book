D3 CHART CODING PLAN — COS30045 Data Storytelling Page
========================================================
Branch: claude/data-storytelling-page-IKWiT
Source spec: charts_features.txt
Stack: vanilla JS + Vite, D3 v7 only

----------------------------------------------------------------
0. WHAT WAS BUILT
----------------------------------------------------------------
Four D3 chart modules under src/charts/, each mounting inside the
existing .placeholder-canvas div of its chapter:

    src/charts/theme.js                — shared tokens + helpers
    src/charts/ch1-trend.js            — national line, phase-coloured
    src/charts/ch2-states.js           — map + click-drill (line × bar)
    src/charts/ch3-demographics.js     — small-multiples horizontal bars
    src/charts/ch4-roaduser.js         — dumbbell chart

main.js boots scrollytelling first, then kicks off each chart in a
try/catch so a single chart failure can't take the page down.

----------------------------------------------------------------
1. DATA PIPELINE
----------------------------------------------------------------
One-shot Python converter:  scripts/build_data.py
Re-run after any change to transformed_datasets.xlsx:

    python3 scripts/build_data.py

Inputs:
    thanh_analysis/datasets/transformed_datasets.xlsx
        (sheets: publication, state, state_summary, population, ...)
    public/data/au-states.geojson
        (fetched once from tonywr71/GeoJson-Data, ~239 kB)

Outputs (public/data/):
    national_trend.json       11 rows   [{ year, hospitalisations, admission }]
    state_totals.json          8 rows   [{ state, cases }]
    state_trend.json          88 rows   [{ state, year, cases, bed_days }]
    population.json           99 rows   [{ state, year, population }]
    age_sex.json              21 rows   [{ age_band, sex, cases, bed_days }]
    road_user.json            12 rows   [{ road_user, cases, bed_days }]

Two filter rules are applied at build-time (NOT at runtime):
    - road_user.json drops every row where road_user = "Not applicable".
      Mirrors the page-level filter in the final pbix.
    - age_sex.json drops rows whose age_band reads "missing", "not
      stated", or "unknown" (the missing-group rule from the spec).

Admission column for chart 1 is computed in Python with the same
DAX rule shown in the spec:
    year == 2011                          -> "Hospitalised injuries"
    2012 <= year <= 2016                  -> "Change in admissions 2012"
    year >= 2017                          -> "Change in admissions 2017"

----------------------------------------------------------------
2. SHARED MODULE — src/charts/theme.js
----------------------------------------------------------------
- colors:        read from CSS custom properties at runtime, so the
                 charts inherit the page's dark-mode palette automatically.
- phasePalette:  three-tone admission palette keyed by category label;
                 reused by ch1 and the VIC/NSW line in ch2's drill view.
- fmt:           d3.format wrappers — fmt.int (comma) + fmt.compact (1.2M / 250k).
- mountSvg:      empties .placeholder-canvas, mounts a responsive
                 viewBox-based <svg>, returns the d3 selection.
- drawGrid:      dotted-light-gray grid (vertical + horizontal) tuned
                 to the spec ("dotted light gray grid" everywhere).
- makeTooltip:   floating div appended to <body>, position: fixed,
                 follows cursor; .show(html, ev) / .move / .hide.

----------------------------------------------------------------
3. CHART 1 — National line  (#chart-1-trend)
----------------------------------------------------------------
File:    src/charts/ch1-trend.js
Sheet:   publication

Render
    Annotated line over years, segments coloured by admission category:
    grey (2011) → accent (2012–2016) → amber (2017–2021).
    Dotted-grey grid background, both axes, axis titles, dot per year.

Interaction
    Per spec: hover on the line/year intersection pops a tooltip with
    year + case count. Implementation = invisible vertical hit-rects
    one per year (snap-to-year behaviour, fewer false hovers than
    bare-point hits). Hovered point gets r 5 → 8.

Legend
    Horizontal swatch + label, drawn from phasePalette in the SVG's
    top-left margin — matches the in-PBI legend by reusing the SAME
    admission categories the data was tagged with at build time.

----------------------------------------------------------------
4. CHART 2 — Map + click-drill  (#chart-2-states)
----------------------------------------------------------------
File:    src/charts/ch2-states.js
Sheets:  state_summary (totals + trend), population (drill bar)
Geo:     public/data/au-states.geojson (8 features)

Render — MAP layer
    GeoJSON drawn with d3.geoMercator().fitSize(...) so it scales to
    the SVG. Each state polygon = accent-bg fill + border stroke.
    Per-state bubble at d3.geoCentroid(feature), radius scaled by
    sqrt(cases). Label = state code (NSW / VIC / ...).

Interaction — MAP layer
    - Hover bubble → tooltip "TOTAL <cases> · click to see more →".
    - Click bubble → swaps mapLayer.style('display') to 'none' and
      reveals drillLayer.

Render — DRILL layer (line × bar combo)
    - Back button top-left ("← Back to map"); click closes drill.
    - Title = full state name.
    - X axis: shared year scale.
    - Left Y axis: cases (accent line).
    - Right Y axis: population (muted bar, fill 0.35 opacity).
    - Population is drawn FIRST (z-order behind), then the cases line.
    - For VIC and NSW, the cases line is rendered as three segments
      using phasePalette — VIC switches at 2012, NSW switches at 2017
      (matches the spec's "change in admission" note).
    - Bottom legend shown only when the state is VIC or NSW.

Interaction — DRILL layer
    Hover each population bar / case dot → tooltip with year + value.

Why this design
    Two SVG <g> layers + display toggle is the simplest state machine
    that still allows a smooth back-and-forth. No router, no global
    state — encapsulated entirely inside initCh2().

----------------------------------------------------------------
5. CHART 3 — Small-multiples horizontal bars  (#chart-3-demographics)
----------------------------------------------------------------
File:    src/charts/ch3-demographics.js
Sheet:   publication → age_sex.json (aggregated)

Render
    One panel per age band, stacked vertically. Each panel has two
    side-by-side horizontal bars:
        left  = cases   (accent)
        right = bed days (muted)
    Value labels sit at the right end of each bar (per spec).
    Vertical dotted grid lines on every panel (per spec).
    Age label sits to the left of the row (anchored end).

Slicer (PRIMARY interaction)
    Drawn inside the SVG above the panels: 3 pill buttons —
    [All] [Female] [Male]. Click → updates activeSex, re-aggregates
    via d3.rollups, and re-renders with d3.transition().duration(450)
    so bars morph rather than redraw. Pill style toggles via fill +
    stroke from accent / accent-bg.

Notes
    - Missing age groups are dropped at BUILD time (build_data.py)
      so the chart never sees them.
    - AGE_ORDER is hardcoded ascending so the panels never sort
      alphabetically.
    - The bed-days scale is independent of the cases scale (each
      panel column has its own xLinear) — this is what makes the
      bar lengths comparable across age bands within each metric.

----------------------------------------------------------------
6. CHART 4 — Road-user dumbbell  (#chart-4-mechanism)
----------------------------------------------------------------
File:    src/charts/ch4-roaduser.js
Sheet:   publication → road_user.json (already filtered)

Render
    Y axis = road user (band scale), ordered by cases descending.
    X axis = a single linear scale spanning max(cases, bed_days),
    so the two dots share one ruler. Dotted vertical grid lines.

Per row
    - <line> from the smaller of (cases, bed_days) to the larger,
      stroke = border color.
    - <circle> at cases (accent fill, r 8).
    - <circle> at bed_days (muted fill, r 8).
    - Value labels next to each dot, anchored start/end based on
      whichever value is rightmost.

Legend
    Top-left, two-item: "Count of cases" (accent dot) and "Bed days"
    (muted dot).

Interaction
    Whole row gets a mouseenter / leave: both circles transition
    r 8 → 11; tooltip shows road user, cases, bed days, bed days/case.

Baked-in filter
    Explicitly verified at module load: any "Not applicable" rows
    that leak through will console.warn. The filter is enforced at
    the data layer (build_data.py), NOT exposed as a UI control,
    mirroring the page-level filter in the final pbix.

7. WIRE-UP — src/main.js
----------------------------------------------------------------
    import { initCh1 } from './charts/ch1-trend.js'
    import { initCh2 } from './charts/ch2-states.js'
    import { initCh3 } from './charts/ch3-demographics.js'
    import { initCh4 } from './charts/ch4-roaduser.js'

    function initCharts() {
      [initCh1, initCh2, initCh3, initCh4].forEach((fn) =>
        Promise.resolve().then(() => fn()).catch(console.error)
      )
    }

The existing scrollytelling glue (IntersectionObserver + stepchange
CustomEvent) is preserved untouched. The current chart modules do
not yet listen to stepchange — they render once on load. When step-
driven behaviour is wanted, each module can hook in via:

    const sticky = document.querySelector('#chart-1-trend').closest('.chart-sticky')
    sticky.addEventListener('stepchange', (e) => updateStep(+e.detail.step))

----------------------------------------------------------------
8. STYLING NOTES
----------------------------------------------------------------
- All dimensions come from CSS variables, so dark mode JUST WORKS.
  No JS theming logic required.
- The .chart-placeholder containers use a hatched canvas in CSS for
  the "no chart yet" state. mountSvg() resets the .placeholder-canvas
  to a plain block so the hatching disappears the moment a chart
  mounts.

----------------------------------------------------------------
9. RE-BUILDING / RUNNING
----------------------------------------------------------------
    npm install
    python3 scripts/build_data.py        # rebuild public/data/*.json
    npm run dev                           # Vite, base = /cos30045/.../design-book/
    npm run build                         # writes dist/

The Vite base path is /cos30045/s104358130/design-book (Swinburne
Mercury deployment). All fetches inside the chart modules use plain
relative paths (data/foo.json), so the base is applied automatically.
